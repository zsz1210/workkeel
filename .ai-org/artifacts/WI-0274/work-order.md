# First-use guidance and actual process recovery

The maintainer approved priorities 1 and 2 with OK on 2026-09-25: improve first
use and qualify interrupted execution. Existing authorization includes scoped
implementation, verification, actual independent review and ordinary PR merge.

## Scope and acceptance

Add a read-only `workkeel start` entry that identifies Git/project setup, retains
legacy mode, checks the native instruction bridge and offers incomplete policy
and brief drafts. Explicit `--request` uses the existing intake preview. Unknown
identities, approval, scope and data decisions remain unresolved. No inferred
permissions, file writes, initialization, model calls, migration or dispatch.
Give concrete next commands as argument arrays, not interpolated executable shell.
Do not return ready on malformed pins, instruction conflicts or invalid briefs.

Exercise a real child-process kill after a deterministic local adapter writes
an effect but before the framework records its result. Confirm live-lock recovery
is refused, a stopped runner can be recovered, uncertain work cannot redispatch,
and evidence-backed reconciliation resumes a later step without repeating earlier
effects. Replay must stay idempotent; task acceptance stays separate. Retain raw
records, phase timings, effect counts and first failures. This is actual process
recovery with an offline adapter, not a model crash, cross-machine qualification,
universal exactly-once guarantee or performance comparison.

## Design and verification

Reuse existing project readers, instruction preview, intake preview, execution
locks, journal and reconciliation. No durable task or workflow schema changes.
Document the additive public read-only CLI projection in an ADR before Build.
CLI interaction only; browser UI is unchanged. Standard risk/profile; root uses
agent-rikku for implementation. Distinct actual reviewer supplies agent-lulu's
judgment, at most one GPT-6 Sol medium review turn up to 300 seconds, with one
same-scope repair and fresh review if needed. This follows prior approved model
choice and required independent QA; no benchmark/model-quality claim.

Use existing dependencies without installing anything. Run focused onboarding
and recovery checks, full npm run verify on the exact candidate, Doctor, required
CI and normal merge. Preserve original toolkits, credentials, global settings and
historical evidence. Stop after runtime sync and report; exclude priorities 3-5,
Gateway, publication, dependency changes and additional experiments. Rollback is
a reviewed revert of product commits with evidence retained.
