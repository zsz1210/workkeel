# Daily task entry and evidence-first observation

The maintainer approved the proposed daily entry, handoff summaries, ongoing
measurements and observer interface, followed by verification and ordinary PR
integration on 2026-09-25. The subsequent repository audit is the prioritization
input. No package release, deployment, new dependency, global setting change or
historical evidence deletion is included.

## Scope and acceptance

- A single brief can be previewed as a complete native task contract and creation
  request, then applied with the exact preview fingerprint. Existing approval,
  policy, path, actor and task guards remain authoritative. Preview cannot run a model.
- Read-only task summaries expose lifecycle, handoff, review, evidence and next
  action, and optional explicit task links/check observations without claiming
  that a workflow completion is acceptance.
- The loopback monitor offers attention-first overview, task detail and usage /
  quality views. It preserves unknown/partial data, safe rendering, capability
  protection and no-write semantics. Normal refresh reads the run index once.
- Partial failures are visible without converting unknown totals to zero. Legacy
  history does not consume the visible native-task limit.
- Runtime data, local acceptance and optional external observations have distinct
  provenance. No inferred billing, completion percentage, live process heartbeat,
  universal efficiency ranking or access to unrelated conversations.
- English/Japanese/Traditional Chinese roadmap and entry guidance agree on the
  current task-first source and retained compatibility boundary.
- Full offline verification, responsive browser verification, actual independent
  candidate judgment and a bounded real-task observation before integration.
- Produce an external retention index and bounded archive/readback verification;
  preserve source history and leave destructive cleanup as a separate decision.

## Design and risk

Use existing native task operations. Add a brief translator with deterministic
fingerprint binding to project policy and referenced approval bytes; never grant
authority from prose alone. Add a read-only task-summary projection and a bounded
optional report contract. Reported links/checks are observations only, bound to
an exact revision with an explicit timestamp/source; only validated schemes are
rendered as links. Unknown or stale metadata cannot certify acceptance.

The observer is a single-project foreground service. Tabs, search and filtering
are local UI state. Errors isolate data only where attribution is trustworthy;
unknown run identity contaminates all measurement totals. No new CORS, mutation
routes, arbitrary file readers, provider connections or background collectors.

Current coordinator owns product/spec/UI/implementation administration. A distinct
actual reviewer must judge the final candidate; changing a label is not review.
Use bounded existing Workkeel/Codex measurement facilities for the already
authorized real-task validation. Record actual model and unknown coordinator use.
At completion stop after this delivery and archival report, without a new benchmark.

Rollback is an ordinary revert of the integrated PR; canonical historical records
and prior reports are retained. This approval authorizes normal PR integration.
