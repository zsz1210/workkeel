# Task observer UI brief

UI/UX responsibility: agent-yuna; implementation: agent-rikku. Code-first delivery
for an optional local read-only surface. The discussed mockup informs hierarchy;
the executable result and responsive browser checks are the acceptance evidence.

Three surfaces: attention-first overview, task detail, and usage/quality. Show
actionable next steps, acceptance evidence and freshness ahead of raw operations.
No organization chart, global model picker or execution buttons. Search and
status filters preserve keyboard navigation. Detail shows actual handoff/review,
revision-bound checks and optional validated conversation/PR links.

Required states: loading, empty, no access link, complete, unobserved, partial,
per-task read failure, whole-snapshot failure, stale metadata, recovery and no
results. Test desktop 1440px and mobile 390px, keyboard focus, no page overflow,
no executable untrusted text, reduced motion and light/dark readable contrast.

Use system typography, quiet blue/teal surfaces, clear headings and restrained
status color with textual labels. Costs remain unknown when unobserved; usage
coverage never implies whole-task quality. Do not invent completion percentages.
