# Workkeel automation and public delivery

## Authority and scope

The repository maintainer approved the P01–P10 next-phase plan and explicitly
requested continued implementation through completion on 2026-09-23, including
appropriate model delegation, OSS licensing/notices and a final misleading or
obsolete-content audit. This work order records that request, not a new grant.

Deliver a task-coordination framework with an opt-in executable graph, task/node
model routing, contextual tool-output compression, native coding-agent onboarding,
readable documentation and measured verification. Existing task acceptance,
history, identities and host permissions remain authoritative. Existing test
slimming, runner design and verification requirements are not to be replaced.

No npm publication, deployment, global tool upgrades, unbounded model spend,
credentials in project files, destructive history cleanup or disabled safety
controls are authorized. A live gateway test requires its actual service,
approved models, data policy and spend limit. Missing live authority does not
prevent offline implementation, protocol tests and local process verification.

## Acceptance

Maintainer clarification during implementation: the primary target is the existing
ChatGPT-subscription Codex login, selecting Luna/Sol for suitable steps instead of
inheriting Astra everywhere. No additional API key or LiteLLM service is available.
Bounded synthetic subscription qualification is part of this implementation;
LiteLLM remains optional with live qualification pending external configuration.
Do not change the account, global model defaults, subscription plan or credits.
Record actual usage as reported; never infer monetary or quota savings from tokens.

1. Define shared runtime start/resume/cancel/result and qualification contracts.
   Reject unsupported boundaries rather than widening them; a runtime adapter is
   a trusted host integration, not a newly invented security sandbox.
2. Execute graph dependencies, parallel branches, conditional edges, bounded
   feedback loops, approval interrupts, cancellation and durable recovery. Never
   infer exactly-once external side effects or acceptance from graph completion.
3. Automatically choose among authorized model profiles at task/node boundaries;
   pin the selection on resume, preserve explicit choices, record the reason and
   observed model, and stop on unavailable/budget/compatibility failures. No
   silent provider fallback or self-modifying routing policy.
4. Apply approved Headroom settings to eligible outputs through the native
   Workkeel entrypoint; protect instructions and canonical sources; retain exact
   originals and lossless-by-default/failure passthrough behavior.
5. Preserve existing AGENTS/CLAUDE instructions, expose Workkeel onboarding and
   project Skill discovery without claiming prompt instructions enforce a sandbox
   or that recorded Skill references prove successful use.
6. Preserve fixed/native model operation. Qualify LiteLLM and coding-agent wire
   interactions against primary docs and installed versions; label simulated,
   offline, real process and live model results separately.
7. Deliver a newcomer-oriented, structurally aligned English/Traditional Chinese/
   Japanese README, editable workflow/architecture diagrams with visual review,
   conventional terminology and a complete representative usage path.
8. Review selected OSS versions and their dependency/license closure. Preserve
   required notices with distributions, distinguish remote services from vendored
   code, and avoid unlicensed/enterprise-only copying. Report uncertainty rather
   than claiming a universal legal guarantee.
9. Record exact-candidate tests, actual elapsed time and measured/unknown token
   and cost values. Complete independent Agent review. Do not duplicate expensive
   full verification on every intermediate edit.
10. Audit current public entrypoints and generated content. Correct misleading
    guidance; remove only proven obsolete material with references checked and
    Git recovery available. Preserve historical evidence and compatibility data.

## Sequence and stop boundaries

Contract/design and targeted audits precede behavioral code. Build the smallest
complete runtime path, integrate graph/routing/compression, then validate and
document actual outcomes. Formal QA uses a distinct Agent Identity. Repository
integration follows the existing PR policy; publication and live spend remain
separate. Do not label an unqualified live integration complete.

## Risk review

Standard cross-system implementation, not a security-boundary product or production
release. Approved tasks and host-owned execution controls are not replaced.
Failure-sensitive areas are durable state, duplicate side effects, stale approval,
concurrent writers, model/provider drift, secret exposure and misleading claims.
Unsupported host containment must block launch or require an external enforcing
host; never downgrade the task contract to make an adapter fit.

## Rollback

Keep all changes on the isolated `codex/workkeel-automation` branch. Revert product
commits through normal review, preserving execution records and original outputs;
do not delete markers or rewrite previous evidence to simulate success.
