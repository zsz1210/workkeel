# Governance

Workkeel is maintained by the repository owner, who decides scope, merges,
security responses, and releases. A task's Agent Identity or Principal
attribution is a Workkeel record; it does not grant GitHub permissions.

Changes to lifecycle authority, public APIs, ownership boundaries, security,
dependencies, licensing, or external integrations need a documented decision
and proportionate review. A different registered Agent reviews an exact
candidate before an authorized Principal accepts the task. GitHub checks and
task acceptance are separate from merge and release authorization.

The public repository contains framework source, documentation, examples, and
reproducible tests. Actual maintainer task state and evidence are private and
backed up separately. See [ADR-0083](docs/adr/0083-public-source-private-state.md).
Contributors should use the [contribution guide](CONTRIBUTING.md) and this
checkout's [AGENTS.md](AGENTS.md) and [native setup guide](docs/getting-started/workkeel.md).
