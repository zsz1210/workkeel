# Workkeel 產品路線圖

[English](roadmap.md) | [日本語](roadmap.ja.md) | **繁體中文**

Workkeel 串接已批准的任務、Coding Agent 執行、交接與驗證結果。
新專案使用 task-first 協調，不需要公司職位。框架 repository 使用原生流程，舊紀錄以唯讀方式保留。

## 開發來源已有的能力

目前發布候選為 Alpha.34；registry 發布仍待驗證。

- 原生任務契約、範圍內認領、精確候選版本交接、不同 Agent 審閱與明確驗收。
- 沿用相同任務檢查的日常 brief 預覽／套用入口。
- 原生經驗驗證、多語搜尋字詞、任務採用及來源影響查詢；符合 Skill 提案条件不會自動啟用。
- 選配的前景觀察頁：工作總覽、任務證據、交接摘要、逐任務用量／品質；唯讀且限單一專案。
- 選配圖形工作流程與政策模型選擇，透過明確設定的 Codex 訂閱 host 執行；自動執行仍屬實驗性。
- 工作流程量測、未知／部分覆蓋與有來源的檢查／連結觀察；不自動量測原生對話。

更名後的 Workkeel 套件尚未發布。歷史 Temple Alpha.33 的可用狀態不代表目前來源已發布，
也不代表新功能已取得完整資格。合併 PR 與套件發布、部署分開。

## 目前優先事項

1. 讓一般已批准工作能從使用者的開發工具方便開始與接手。
2. 清楚區分任務驗收、執行進度與外部觀察。
3. 累積具代表性的真實任務品質、返工、耗時與 token 證據。
4. 只在範圍、模型、工具與驗收檢查一致時比較流程。
5. 透過現行文件與經驗證的封存降低維護負擔。

一次成功樣本不足以證明通用可靠度、節省幅度或模型優劣。保留負面結果與量測限制。

## 相容性與選配工作

舊 Temple 專案保留指示、職位、schema 與固定 launcher。明確遷移僅支援文件列出的
靜止 Solo 範圍；不要直接更名或丟棄 canonical 歷史。舊 Console、federation、
外部任務系統 adapter 與檢索擴充仍是選配能力。

固定 LiteLLM gateway 的實測仍等待運作條件。Gateway 自動路由、多機協作、
廣泛 provider 驗證與跨專案觀察是獨立後續工作。

## 歷史計畫與維護

Phase 1–4 文件記錄早期 Temple 里程碑與設計脈絡，不是 task-first 入門路徑或目前待辦。
大型實驗 runner 保留作為重現工具，保留凍結協定及版本限定的結果；
只有明確限定的驗證工作才再次使用。

歷史證據與截圖需要保留索引，以及匯出／讀回驗證後才能評估移動。
受管理安裝副本與專案模板即使內容相同，所有權仍不同。
日常維護不包含依檔案年齡刪除或重寫 Git 歷史。
