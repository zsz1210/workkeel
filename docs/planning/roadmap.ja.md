# Workkeel ロードマップ

[English](roadmap.md) | **日本語** | [繁體中文](roadmap.zh-TW.md)

Workkeel は承認済みタスク、Coding Agent の実行、引き継ぎ、検証結果をつなぎます。
新規プロジェクトは会社の役職を必要としない task-first 方式を使います。
フレームワーク自体のリポジトリは従来の自己運用契約を維持しています。

## 開発ソースで利用できる機能

- タスク契約、範囲を限定した担当宣言、正確な候補リビジョンの引き継ぎ、別 Agent のレビュー、明示的な受け入れ。
- 同じタスク検証を利用する日常 brief のプレビュー／適用。
- 任意の前景オブザーバー：作業一覧、証拠、引き継ぎ要約、タスク別使用量／品質。読み取り専用で単一プロジェクトが対象。
- 明示的に構成した Codex サブスクリプション host による任意のグラフ実行とポリシーモデル選択。自動実行は実験段階。
- ワークフロー計測、不明／部分的なカバレッジ、出所を記録したチェック／リンク観測。通常の会話は自動計測しません。

改名後の Workkeel パッケージは未公開です。過去の Temple Alpha.33 の提供状況は、
現在のソースの公開や新機能の資格確認を意味しません。PR マージと公開／デプロイは別です。

## 現在の優先事項

1. 承認済みの日常作業を Codex の会話から簡単に開始・再開できるようにする。
2. タスクの受け入れ、実行進捗、外部観測を明確に分ける。
3. 実際の代表的タスクから品質、手戻り、時間、token の証拠を集める。
4. 範囲、モデル、ツール、受け入れ確認を揃えた場合だけ工程を比較する。
5. 現行ドキュメントと検証済みアーカイブにより保守負担を減らす。

一度の成功は一般的な信頼性、節約率、モデルの優劣を証明しません。
否定的な結果と計測範囲も保持します。

## 互換性と任意の作業

従来の Temple プロジェクトは指示、役職、schema、固定 launcher を維持します。
明示的な移行は文書化された停止中 Solo の範囲に限ります。正本の履歴を改名・破棄しません。
旧 Console、federation、外部トラッカー adapter、検索拡張は任意の機能として残ります。

固定 LiteLLM gateway の実測は運用条件待ちです。Gateway 側の自動ルーティング、
複数マシン連携、幅広い provider 検証、プロジェクト横断観測は別の後続作業です。

## 過去の計画と保守

Phase 1–4 文書は以前の Temple のマイルストーンと設計背景です。
現在の task-first 入門やバックログではありません。大規模な実験 runner は再現用として
凍結した手順と版ごとの結果を残し、明確に限定された検証でのみ再利用します。

過去の証拠と画像の移動は保持索引、エクスポート検証、読み戻しの確認が前提です。
管理対象のインストール副本と配布テンプレートは、同じ内容でも所有権が異なります。
日常保守に経過日数による削除や Git 履歴の書き換えは含めません。
