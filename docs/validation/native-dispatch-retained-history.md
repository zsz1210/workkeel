## Compatibility retirement criteria

| Material | Handling |
| --- | --- |
| Current task entrypoints/instructions | Native Workkeel; no new Temple task creation |
| User-visible legacy Skill entries | Label compatibility origin and hide by default |
| Historical tasks, approval/evidence pins | Retain exact bytes |
| Temple aliases, overlay and fixtures | Retain while supported legacy projects use them |
| Old ADR descriptions of Positions | Historical decisions; current native instructions take precedence |

Removing legacy support would require a separately scoped compatibility release,
migration guarantees and explicit retention decisions. This integration introduces
no new legacy dependencies, deletions, schema renaming or retroactive acceptance.
