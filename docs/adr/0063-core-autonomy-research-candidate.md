# ADR-0063: An isolated core autonomy research candidate

Status: Accepted as an offline prototype; not a default change.

## Context

Lean already permits goal-owned implementation and combined administrative
operations. Further autonomy should reduce repeated role instructions and state
assembly while preserving authority, provenance and distinct acceptance. The
an opt-in candidate was approved after an overall direction review.

## Decision

Separate the control responsibility from product implementation. A coordinator
retains the actual Temple Work Item, ownership, risk assessment, original approved
sources, budgets and evidence. An isolated product worker receives one compiled
contract with deduplicated required context. It chooses intermediate methods;
there is no mandatory extra design report, role decomposition or status essay.

The prototype is a repository-only contract compiler, checkpoint projection and
pinned-CLI completion adapter. It is not an installed workflow or an authorization
engine. Only existing low-risk bounded Lean Build/Test qualifies. Compilation
reassesses the current workflow and retains named prebuild evidence, active claim
and distinct Verifier. All semantic judgments come from actual separate evaluation;
the adapter does not infer correctness from the presence of files.

Keep a small recovery record: contract digest, exact candidate, observed evidence,
unresolved items and next action. Hashes bind content, not human approval or truth.
Callers must obtain snapshots and expected digests from trusted control state;
participant-supplied snapshots cannot substitute for that state. The experiment
adapter must enforce product/control isolation and permitted tools before launch.

Current native instructions remain in force in the control checkout and in any
ordinary installed Temple project. The separate product worker must not inherit
the control checkout's full administrative task by accident. A fresh-session
runtime rehearsal is necessary before claiming instruction isolation is proven.

Program fixed completion through the existing pinned CLI. It retains current
candidate/evidence/authority/Identity checks and exact-request replay. No model
call, arbitrary test command, lifecycle JSON edit, automatic retry or external
action is exposed by this adapter. Diagnostic failure stops automatic advancement.

## Validation and decision boundary

Use real local CLI fixtures for Build/Verifier/Done and diagnostic recovery, plus
pure negative tests for risk, scope, Identity, missing context, incomplete budget
and checkpoint drift. These prove mechanisms, not model quality or Token savings.

The first proposed live screen is the same complex, reversible interruption task
under current Lean and this candidate, crossed with Terra Medium and GPT-6 Medium.
Four cells and one repetition are diagnostic. Freeze product seed, acceptance,
semantic interruption point, runtime/model contract, complete buffered budget and
actual launch authority before dispatch. Unknown values remain unknown. No current
template is silently relabeled as a qualified live execution mode.

If a protection needs a particular checkpoint or independent role, keep it. If a
method provides no material benefit for a task class, make it optional. High-risk
autonomy remains a separate synthetic qualification effort with existing safeguards.
