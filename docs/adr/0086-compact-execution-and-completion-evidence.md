# ADR-0086: Compact execution views and explicit completion evidence

- Status: Implementation candidate; independent acceptance required

## Context

A passing implementation test does not prove that every agreed interface exists.
Lifecycle stage cards also cannot explain actual execution, allocation or handoff.
Foregrounding every identifier and evidence field hides the user's next decision.

## Decision

The native observer and desktop workspace share read-only activity, interval and
dependency renderers. Activity, Agent identity, model selection and acceptance
remain separate concepts. Show current situation and required action first;
disclose records, identifiers and measurement provenance on demand. Draw only
recorded intervals, retain unknown and explicit zero, and expire running reports.
Dependency diagrams include every mandatory component; they never accept a goal.

Strengthen the existing native Work Skill in both maintainer and installed copies.
Compare every approved criterion with exact candidate evidence, repair omissions
within authority, and repeat actual UI inspection before declaring completion.
The installed `task evidence-check` command checks authored report coverage and
artifact digests without models or writes. It cannot infer semantic correctness,
usability, review independence or Skill activation. The declared UI mode and
observations remain claims for the actual reviewer to challenge. Independent
review may still be pending at handoff; retain that uncovered gate and produce
the final completion report only after the actual decision.

## Consequences

No new vendor, optional integration, writable acceptance store or framework-wide
learned rule is introduced. Native handoff, distinct-Agent review and approver
closure remain authoritative. Real reports and screenshots stay in private
development storage; only reusable code, guidance and synthetic regressions ship.
