# ADR-0058: Opt-in bounded Lean entry

Status: Accepted for bounded compatibility implementation.

## Decision

Connect ADR-0055/0056 material acquisition and ADR-0057 completion through read-only `context enter`. Explicit Work Item, Position, Agent and Principal arguments select the operation; `--no-write --json` are mandatory. Invoking this command opts in. Existing Context/packet defaults and workflow selection remain unchanged.

Reassess current Lean eligibility and actor sponsorship/membership, stage and claim binding. Only low-risk bounded Build/Test without UI, unresolved scope, conflicting ownership, active workers or unsettled recovery/diagnostics may receive stage material and claim/finish navigation. Test entry preserves a distinct Verifier Identity and exact Developer handoff candidate. No eligible claim is invented. Standard, High-Assurance, recovery and unclear cases return the existing body-free compact route with explicit fallback reasons. Failed acquisition emits no incomplete collection disguised as complete material.

Bind route, explicit actor/Principal, purpose, full selected-source authority and relevant runtime/diagnostic state to the entry digest. A changed expected binding rejects without writes. Read-only eligibility and operation hints do not pass future mutation guards. A claim or finish must revalidate its own exact request through existing operations; entry and finish preview digests are different contracts.

Use the existing transient stage packet, retaining whole mandatory instructions, policies and evidence. For this optional entry path, route the installed `temple-work` Lean execution reference as its stage procedure. Full ordinary packet behavior is preserved. Receiving a body allows the caller to read it; delivery alone proves neither reading nor comprehension. Do not reread already-read, available, unchanged whole bodies solely because they came from this response. Required unselected references and complete sources explicitly required by the task still must be read. Projected inventories are derived selections with full-source provenance, never canonical replacements.

Core source templates describe the optional route; update the toolkit's exact managed entries through supported upgrade. Bootstrap and native provider instruction loading remain mandatory, and no session-memory shortcut is introduced. This is an extension of the existing delivery Skill, not a new Skill, fourth profile, model router or dependency.

## Verification and limits

Exercise real CLI cold Builder/fresh Verifier entry and explicit finish in an isolated initialized installation, plus ineligible and stale/unsafe adversarial cases. Verify installed AGENTS/TEMPLE/Skill sources and provider import bridge, full instruction/evidence coverage, no source-body persistence and unchanged canonical bytes from entry. These deterministic checks prove installed command routing and acquisition, not a model's autonomous choice or instruction comprehension. Full tests and distinct QA must pass before closeout. No Token, speed or quality advantage is inferred; a future model comparison remains separate.
