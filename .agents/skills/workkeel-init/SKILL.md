# Native Workkeel initialization

Use the reviewed local Workkeel CLI and Node.js 24+; Git is needed for task
candidates. Read the project's native instructions and the shipped getting-started
guide. If unavailable, report the missing dependency without installing it.

Start with read-only status/start guidance. Establish the user's actual identities,
review separation, repository boundaries and approval before preparing policy.
Read-only diagnosis does not permit initialization or migration.

For an approved new project, use native init with the approved policy. For an
approved legacy migration, preview the exact retained state and policy, then apply
only that fingerprint. Preserve historical records and unfinished acceptance.
Active claims or unsupported policy conditions require resolution, not relaxed checks.
Do not rewrite temple.lock, evidence digests or canonical records by hand.

Run native Doctor and instruction preview after application. Report what changed,
the effective workflow, validation failures and the next task-intake step. Valid
setup does not approve execution, delegate work or accept an existing task.

Provenance: original instructions for the native Workkeel CLI. The legacy
temple-init entrypoint remains historical compatibility material.
